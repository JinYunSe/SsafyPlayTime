# Item 작업 가이드라인

## 목적
- 아이템 작업 시 파일 위치를 빠르게 판단할 수 있도록 기준을 제공한다.
- 여러 작업자가 동시에 수정하더라도 충돌과 회귀를 줄인다.
- 런타임 연결을 깨지 않고 기능을 확장하는 것을 우선한다.

## 기본 원칙
- 기존 `namespace`, `public class`, `.meta`는 함부로 변경하지 않는다.
- 캐릭터 로직, 필드 로직, 런타임 로직, 개발용 테스트 로직을 섞지 않는다.
- 새 기능은 작은 단위로 나누고, 공용 수정은 필요한 범위만 최소화한다.
- `ItemScene` 전용 코드는 실게임 로직에 직접 의존하지 않게 유지한다.
- 임시 디버그 입력은 `Dev/` 안에서만 관리한다.

## 폴더별 책임
- `Catalog/`
  - CSV 로더 결과를 합쳐서 실제 아이템 카탈로그를 만드는 영역
- `Common/`
  - 아이템 공용 모델, 상수, 브리지 인터페이스
- `Data/`
  - CSV 파싱과 데이터 로더
- `Runtime/`
  - 아이템 사용, 상태 변경, 버프 적용, 모듈 등록
- `Character/`
  - 캐릭터 손 장착, 입력 연동, 근접 공격, 버프 반영
- `World/`
  - 필드 드랍, 획득, 스폰, 필드 프리팹 해석
- `Dev/`
  - `ItemScene` 전용 러너, 디버그 입력, 테스트 도구
- `Docs/`
  - 구조 문서와 작업 규칙 문서

## 어떤 파일을 수정해야 하는가
### 새 아이템을 추가할 때
1. `Data/ItemTable.csv`에 아이템 정의를 추가한다.
2. 고유 동작이 필요하면 `Runtime/Modules/`에 새 모듈을 만든다.
3. `ItemUseModuleRegistry`에 새 모듈을 등록한다.
4. 손 장착 표현이나 근접 판정이 필요하면 `Character/`를 수정한다.
5. 필드 드랍 방식이 특수하면 `World/`를 수정한다.
6. `Dev/ItemScene`에서 회귀 테스트를 한다.

### 기존 아이템의 수치만 조정할 때
- 가능하면 `ItemTable.csv`와 관련 프리젠테이션 데이터만 수정한다.
- 코드 수정 전에 데이터만으로 해결 가능한지 먼저 확인한다.

### 아이템 사용 연출을 바꿀 때
- 실게임 동작은 `Runtime/`에서 유지한다.
- 테스트용 재생이나 빠른 검증용 로직은 `Dev/Runner/Skills/`에서 분리한다.
- 에셋 경로 변경만 필요한 경우 로직 파일보다 데이터 테이블을 우선 검토한다.

## 수정 금지 또는 주의 대상
- 다른 작업자가 담당 중인 아이템 전용 파일은 불필요하게 건드리지 않는다.
- `Dev/` 코드를 실게임 필수 의존성으로 만들지 않는다.
- 필드 아이템 공통 물리 설정은 맵/환경 담당과 충돌할 수 있으니 신중하게 수정한다.
- 프리팹 참조가 걸린 스크립트는 파일 이동 시 반드시 `.meta`를 유지한다.
- 사용하지 않는 임시 코드라도 `true/false` 분기만 늘리지 말고, 작업 종료 시 정리 가능한 구조로 작성한다.

## 협업 규칙
- 한 작업자는 가능하면 한 아이템 또는 한 책임 영역만 담당한다.
- 공용 파일 수정이 필요하면 변경 이유가 드러나게 메서드 단위로 최소 수정한다.
- 여러 아이템이 공유하는 로직은 `Runtime/` 공용 계층으로 올리고, 개별 예외는 모듈 내부에 둔다.
- 리뷰어가 파일 경로만 보고 의도를 알 수 있도록 폴더 책임을 지킨다.

## 테스트 체크리스트
- 아이템 획득이 정상 동작하는가
- 손 장착 시각이 정상인가
- 사용 입력이 정상 동작하는가
- 드롭 후 재획득이 가능한가
- 다른 아이템 흐름에 영향이 없는가
- `ItemScene`과 실제 게임 흐름에서 둘 다 오류가 없는가
- Unity 콘솔에 새 에러가 없는가

## 커밋 전 체크
- 불필요한 디버그 로그 제거
- 임시 테스트 키가 남아 있는지 확인
- 같은 책임의 파일끼리만 묶여 있는지 확인
- 다른 작업자의 진행 중 파일을 불필요하게 건드리지 않았는지 확인
- `.meta` 포함 여부 확인

## 권장 작업 순서
1. 데이터 정의
2. 런타임 모듈 구현
3. 캐릭터 또는 필드 연동
4. 연출 연결
5. `ItemScene` 테스트
6. 회귀 확인 후 커밋
